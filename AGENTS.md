# RevenueCat assets generation

This independent kit runs without a website checkout or live design connection. Version 0.2.1 provides 610 catalog entries: 291 imported illustrations, 267 reusable parts, 24 storyboard states and 28 native data presets. Registrations include source variants and fixed asset fragments; they are not all fully native widgets. Use the installed catalog as the available set. Do not claim complete source-library coverage or pixel-identical rendering.

- Use English for plugin-owned interfaces, catalog labels, search and clipboard messages, review pages, documentation and metadata, regardless of the conversation language. Set generated HTML to `lang="en"`. Preserve designer-supplied artwork copy unless the user requests a copy change.
- When working from the plugin, follow `skills/revenuecat-assets-generation/SKILL.md` and create an independent copied project, never edit the installed plugin cache. Generated projects omit the plugin skill; use their local README and catalog for the supported workflow.
- For a creative request, the agent does the complete authoring, generation and visual review. Search `npm run catalog -- <terms>`, then resolve the requested component with `--id` or `--name` plus `--describe --json`. Keep its exact ID; never silently substitute similar artwork. Follow `catalog/composition.md`, author a separate scene JSON and run `npm run generate -- --props <scene.json> --output <new-or-empty-directory> [--format png|mp4|both]`. Both media formats are the default. Return the generated artifacts, review page and editable scene; do not ask the user to assemble or export in Studio.
- Use `npm run gallery` and `out/library/index.html` for complete visual library browsing. Import-batch pages are subsets, not the library total. Distinguish registered components, source variants, reusable parts and internal motion targets. Do not present all imported React wrappers as fully native or fully editable; see `catalog/implementation.md`.
- Studio is optional preview only. It includes `SelectedShowcase` to play “Build, connect, grow” and `SelectedOverview` to browse the selected artwork. The agent opens a custom-props preview with `--composition Scene`; composition and generation remain agent-run.
- Figma source identity is the pair `fileKey` and `nodeId`. Preserve existing public component IDs; never resolve cross-file artwork by node ID alone. Assembly parts are separate from requested selection roots and must not inflate the selection count.
- Keep the scene contract aligned with `src/composition/schema.mjs` and the examples. The Benchmarks contract remains aligned with `examples/benchmarks.json`, its schema and `catalog/benchmarks.json`.
- Use only the selected component's declared `props` from `src/figma/component-contracts.json`: supported native text, scalar CSS colors, visibility and explicitly declared image slots. Omitted fields preserve the source; props affect one instance. Colors accept the approved palette or the field's original color. Embedded SVG/raster content, gradients and mixed styled text require a reviewed local variation when no field is exposed. Do not invent prop names or imply universal recoloring. Source screenshots are QA references, never implementation layers. Preserve original local assets and their intrinsic dimensions.
- For movement within an illustration, query its exact `--motion --json` contract. Author `internalMotion` against declared native target IDs or their aliases, using local frame keyframes. Keep the surrounding illustration still when the action belongs to an inner element. Read `catalog/internal-motion.md` for supported properties and counter eligibility; do not claim independent control of paths inside flattened SVG/raster fragments.
- For a table/chart inside an imported illustration, inspect its exact `--describe --json` result for `embeddedDataSlots`. Keep the original `illustrationId` and edit only declared `data` slots; query custom input with `--data <embedded-data.json>`. Preserve source geometry and surrounding artwork. Separate `native-*` presets and `type: "native"` remain available for new compositions. Read `catalog/native-data.md`, keep data IDs stable and animate numerical geometry with declared targets. Never infer measured values from designer paths; source chart defaults are illustrative where no dataset was available.
- For structural table edits, use a complete `props.dataset` with columns and rows; do not combine it with sparse cells/columns. For chart point counts, use `props.values` and optional stable `props.pointIds`. Query motion against the actual data after changes. Automatic layout stays within the original usable region and enforces density and range limits. Remove tracks for deleted IDs and replace legacy controls on removed table nodes with declared data targets. The agent must generate and inspect the result; do not shift composition work to the user.
- The original Benchmarks composition retains its copy-only contract. The source summary says `5/7 metrics above median` with six visible rows. Preserve it by default and describe it as editable illustrative copy; do not infer real measurements.
- Keep assets local and dependencies pinned. Before animating, read `catalog/motion.md`: use purposeful group choreography and deterministic frame math, keep ambient float opt-in, and distinguish UI from marketing timing. Preserve composited fractional movement, PNG frame capture and renderer concurrency 1. Run `npm run motion:check -- --props <scene.json>` and review warnings. Deliverables are PNG illustrations and MP4 videos; do not add browser preference handling or reduced-motion modes to the generation workflow.
- Run type checking and lint after implementation edits; render and inspect affected PNGs and play the exported video when visuals change. For small moving UI/text also inspect consecutive frames, and check any requested loop seam. Generated projects omit publisher tests and acquisition tooling; validate their scene schemas and actual output. A new scene JSON needs schema/render validation rather than implementation-mirroring unit tests. Manifest validation does not prove native host installation or skill activation.
